## Local background music removal

- New home action “去 BGM · AI 保留人声” runs two published Spleeter magnitude models with ONNX Runtime 1.24.3, CPU only. SHA-pinned FP16 weights and ARM64 runtime ship with the APK; generated weights are excluded from git and downloaded during build using tooling/prepare-bgm.py. Runtime needs no API key, model-download endpoint or media upload. Original MIT/Apache license notices ship in assets/bgm/NOTICE.txt.
- Input: a video with audio, at most 180 seconds / 1 GiB. First audio track decodes locally to stereo 44.1 kHz PCM. Java STFT and overlap-add use fixed 4096/1024 FFT/hop, 512-frame bounded chunks and centred edge padding. Both model predictions form a Wiener vocal mask; output remuxes the original picture stream and AAC vocals. 44.1 kHz follows the primary Spleeter separation example and the upstream C++ implementation defaults; the converted model's legacy sample_rate metadata is not used to resample audio.
- Operation checks cancellation during IO/DSP and terminates ONNX inference using RunOptions. Temporary media and failed/unpublished MediaStore output are cleaned up. Output requires both valid audio/video tracks before publication. The original file is retained. Long material should first be cut into supported segments.
- Primary implementation references reviewed: k2-fsa/sherpa-onnx scripts/spleeter/separate_onnx.py and offline-source-separation-spleeter-impl.h; Deezer Spleeter MIT license; Microsoft ONNX Runtime Java API/license. The Android implementation does not add a sherpa JNI dependency or a hosted separation service. The exporter/model source and dependency hashes are recorded in tooling/bgm-lock.json / engine-lock.json.

## Verification and limits

- All production Java compiled against Android framework contracts. Final gate passed 11 general JVM suites (391 assertions), 4 actual generated JavaScript suites (77), production yt-dlp format selection (18), production Java DSP and real ONNX model suite (14), and FFmpeg media integration (4): 504 checks. Four release-script tests passed separately. Python syntax and git diff --check passed.
- The neural suite executes both exact published models with the production Java inference/DSP classes on desktop CPU, including cancellation during actual inference, FFT reconstruction, an overlap-add block join, shape/invalid-mask checks, and exact PCM length. Synthetic speech is produced locally with FFmpeg flite; a generated three-tone accompaniment is mixed into it. The test measured vocal projection 0.966 and background projection 0.092 for this one fixture; it requires background attenuation relative to voice, not just a nonempty output. These figures are not accuracy claims for arbitrary recordings.
- The FFmpeg integration uses the same mux command as Android. It checks both tracks, duration within 0.1 second and identical SHA-256 of the original video packet stream. Native ARM64 loading, MediaStore publication, Android UI operation, phone speed/RAM and separation quality on the user's material are not verified by desktop tests.
- Source separation may leave music, damage speech, preserve background singing or remove ambient sound. It is not guaranteed dialogue-only extraction. Existing limitations (two desktop WeChat ports/private Telegram session) remain. Development signing is unchanged; cloud APK build/release status must be checked after push before reporting availability.

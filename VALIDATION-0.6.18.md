# 0.6.18 verification — 2026-10-28 (Asia/Shanghai)

## Scope

The user selected native-phone capability adaptation, accepting that desktop WeChat dependencies and unavailable source remain incomplete. This release implements four native capability entry points, not six complete project ports or six independent parser engines.

- res-downloader entry opens native ordinary-page HTTPS media capture. Ordinary original pages now have the existing download listener previously restricted to helper websites. Device-wide capture, certificates and desktop proxy code are not implemented.
- Youwee / VidBee entries open a native downloader workbench backed by the already bundled shared yt-dlp/Python/FFmpeg engine. Users can parse, preview, choose audio/video queue mode, select native-engine resolution caps and enqueue. Full desktop applications, VidBee transcription/RSS and AI features are not included.
- Youwee v1 import accepts its actual documented extension fields: action=queue_only/download_now, media=video/audio, quality=1080/720/480/360 etc. It verifies host/version/HTTPS, bounds input, rejects duplicates, normalizes a single YouTube watch URL and preserves other signed URLs. It opens native confirmation UI; it does not automatically execute a download based on external input. Unsupported higher quality preferences currently use source quality. This is protocol interoperability, not copied desktop UI code.
- Telegram native public-embed adapter accepts a specific public channel/message URL, supports video and photo links, preserves source/Referer/signatures, excludes cover elements and subsequent posts and rejects private/invite URLs. It does not run the upstream private-channel userscript or import Telegram sessions.
- wx_channels_download still needs desktop WeChat session/proxy infrastructure. qiye45/wechatVideoDownload's current tree contains documentation/binaries/examples, not portable application source. Both show explicit unfinished-native-port status. No API, login session or desktop backend was invented.

# 0.6.12 verification — 2026-10-24 (Asia/Shanghai)

- Automatic Douyin browser results and share-page candidates now share the direct-video prefix checker. A browser URL returning an error or HTML cannot win the original parser race merely because it is HTTPS. The share-page path no longer stops after the first three addresses: it checks up to 24 candidates within an 8-second budget, selecting one usable video while preserving original signed URLs, Referer, User-Agent, source and preview items.
- Prefix checks accept HTTP 200 or a valid zero-based HTTP 206 range, reject known empty/over-2GB totals and compressed transport, and read at most 64 application bytes for MediaSignature. Unknown totals remain subject to the original downloader's full byte limit. A prefix check is not full decoding or proof that an entire media transfer will finish.
- The browser copy is made under its result lock, then the WebView is closed and network checking runs outside the lock on the worker. Probing uses remaining browser time, with per-hop connect/read timeouts at most 3 seconds, deadline checks across redirects/reads, cancellation checks and connection cleanup. Normal downloader timeouts remain unchanged. DNS/platform I/O cancellation timing is not tested on Android.
- Photo works are unchanged. Existing native selectors and known or MIME-declared segmented streams continue through the existing engine rather than being falsely described as verified direct files. No challenge, authorization or DRM bypass is added.
- All production Java sources compile under JDK 17 against Android 35 and the pinned dependencies. Related checks passed: real-HTTP video candidates 34, link parser/security/signatures 31, transfer/native ZIP download and exact media output 46, Douyin search regression 29 (140 assertions total). The new tests use a local HTTP server and an FFmpeg-generated MP4, including 403/404, HTML/JSON, invalid range, oversized total, compressed/short replies, success on a fourth address, signed queries, retained request metadata, connection closure, zero budget, slow body, in-flight cancellation and an invalid browser URL losing the parser race.
- No Android phone/emulator or failing user share link is available. Live Douyin downloads and all three provider sites remain unproven; fixture tests and APK compilation do not establish real-site availability. This release fixes candidate verification and fallback behavior, not a demonstrated end-to-end Douyin unblock.

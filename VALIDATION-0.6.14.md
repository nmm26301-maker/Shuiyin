# 0.6.14 verification — 2026-10-25 (Asia/Shanghai)

- Implemented the optional picker.audio and picker.audioFilename fields documented by the primary Cobalt API source (https://github.com/imputnet/cobalt/blob/main/docs/api.md) in both native HTTP response handling and the actual browser collector. Audio retains signed URLs, filenames, work origin and downloader headers; unsafe optional audio cannot discard valid images. The shared 24-item cap is preserved with audio retained first.
- Four-provider aggregation now retains meaningful descriptions even if no provider returned downloadable media. It clearly reports caption-only outcomes and other provider failures. Whitespace-only descriptions still fail, and a caption can coexist with another provider's video. The existing no-media result UI is now reachable and defaults to the caption tab; media results default to an available video/image/audio tab.
- All production Java compiled with JDK 17, Android 35 and pinned dependencies. Related checks passed: provider HTTP/response adapters 34, parallel search 19, nested diagnostics 22 and actual website collector JavaScript 23 (98 assertions). New cases cover optional album audio, signed queries, filename/headers, unsafe URLs, item cap, caption-only/blank/partial outcomes and browser collection. UI tab selection was compiled but not exercised on a phone.
- No live Douyin download, authorized Cobalt instance, all-three-provider availability or Android device interaction is demonstrated. These changes fix response coverage and result retention, not a proven end-to-end unblock. Existing development signing is unchanged.
